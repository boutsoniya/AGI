Can an AI prove that it completed the task?

An agent saying “done” is not the same as the task actually being done. Reliable systems check the result against the goal.

verificationAI agentsreliability
THE IDEA

Task completion needs evidence. An agent should define what a successful outcome looks like, take the action, then inspect the resulting state. If it was asked to send a file, it should verify that the file was sent to the right person. If it was asked to update a record, it should read the record back and check the changed fields. This is a postcondition check: confirming that the world now satisfies the intended result, rather than trusting the action call itself.

WHY IT MATTERS

Tools can time out, return misleading success messages, act on the wrong item or partially complete a multi-step task. Without verification, an agent may report success after only attempting an action. Evidence-based completion makes failures visible and gives users a truthful status: completed, partially completed, failed or still uncertain.

TRY THIS

Give an agent a harmless task in a test environment: create a note with a specific title and two bullet points. After it reports success, independently open the note and check the title and both bullets. Then deliberately change one bullet in the test data and see whether the agent notices the mismatch instead of claiming the task is complete.

WHERE IT BREAKS

Verification can also be weak. Checking only that a button was clicked does not prove the intended state changed. A stale cache, wrong account or incomplete check can create false confidence. The system must verify the outcome that matters, using an independent and appropriately scoped signal where possible.

TAKEAWAY

A reliable agent verifies the result, not just the action it attempted.

BEFORE YOU READ

An agent clicks “Send” and receives a timeout. What should it report?

A. The message was definitely sent

B. The outcome is uncertain; check the sent state

Answer: B. Exactly. It should inspect the resulting state before reporting success, while avoiding an unsafe duplicate send.
